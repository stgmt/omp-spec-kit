### Confirmed findings
- **Finding ID**: `correctness-2`
  - **Priority**: P2
  - **Defect Class**: `correctness`
  - **File Path**: `src/service/publish.js`
  - **Line Range**: 98–118
  - **Title**: Divergent remote tag is silently swallowed and reported as outcome: 'noop' instead of rejected drift
  - **Observed Behavior**: In `src/service/publish.js:98-118`, when `ledgerRow` exists for an ACTIVE spec version and `remoteTagCommit(remote, tagRef) !== ledgerRow.commitSha`, the code assumes the remote tag is merely missing and attempts to heal it via `git.push`. If the remote tag already exists on origin pointing to a divergent commit (`remoteTagCommit !== null`), the unforced `git.push` is rejected by remote Git (`[rejected] (already exists)`). The `.catch((error) => logger(...))` handler logs the push error, and execution falls through to `return { spec: specKey, outcome: "noop", version: snap.version }`. The tag divergence is never rejected via `reject()`, never recorded in `store.logAccess` (`publish-rejected:VERSION_EXISTS`), and never surfaced in `computeDrift` (which inspects `store.listAccess` for `publish-rejected:` entries).
  - **Expected Behavior**: Tag healing via `git.push` must only be attempted when the remote tag is absent (`remoteTagCommit === null`). When `remoteTagCommit !== null && remoteTagCommit !== ledgerRow.commitSha`, the remote tag has diverged from the immutable ledger. The publisher must report `outcome: "rejected"`, invoke `reject(projectId, slug, snap.version, "VERSION_EXISTS", ...)`, record the rejection in `store.logAccess` (`publish-rejected:VERSION_EXISTS`), and surface the collision in `computeDrift`, rather than swallowing the push failure and reporting `outcome: "noop"`.
  - **Trigger Scenario**: A spec is published and recorded in the ledger at commit C1. An out-of-band commit C2 is tagged with the same version on origin. On a subsequent publish pass (via sync reconciliation, service boot, or spec write), `publishSpec` encounters `remoteTagCommit(remote, tagRef) !== ledgerRow.commitSha`, attempts an unforced tag push which origin rejects (`already exists`), catches and logs the error, and returns `outcome: "noop"`, silently reporting success while masking remote tag divergence from drift reports.
  - **Impact**: Silent data divergence and masked corruption: if an upstream remote tag is created or pointed to an alternate commit out of band, subsequent publish passes report outcome: 'noop' (successful publication), masking the collision from callers and preventing drift reporting from flagging the tag divergence.
  - **Repository Evidence**: `src/service/publish.js:98-118`, `src/service/index.js:46-52`.
