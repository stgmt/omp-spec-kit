### Confirmed findings

**correctness-1 — P2 — `scripts/spec-graph-sync.mjs:172` — spec_patch REFUSED outcome reported as applied**
- Observed: `McpStdioClient.callTool` throws only when `envelope.ok` is falsy (`if (!envelope?.ok) throw …`); `outcome` is never inspected anywhere in the file. The authoring service returns refusals as `{ok:true, data:{outcome:"REFUSED"}}` (`src/authoring/service.js:112-128`, catch-all `:315`), reachable via lock-contention CONFLICT (`src/authoring/transactions.js:350-370`), under-lock fingerprint CONFLICT (`service.js:232,240`), and commit failures. `StatusSweepService.sweep` then records `applied` + logs `sweep-apply` (`src/adapters/youtrack-status-sweep.js:117-124`); the live writeback answers `{applied:true}`.
- Expected: REFUSED must be treated as failure (recorded in `failed` / `applied:false`) — the MCP server itself marks `outcome==="REFUSED"` as `isError` (`src/mcp/server.js:153`).
- Trigger: a writeback/sweep patch collides with a concurrent spec transaction → REFUSED → reported as applied while the spec is never updated.
- Impact: silent spec/tracker divergence reported as success; persistent refusal causes stay invisible; the governed Approve/Verify/Reopen path falsely confirms writes.

**correctness-2 — P2 — `scripts/spec-graph-sync.mjs:479` — sync demotes richer tracker states every run**
- Observed: `upsertOneCard` patches `State` whenever tracker State `!== STATUS_MAP[specStatus]` (exact equality). Verified→Fixed, In Progress→Open on every non-skipped sync.
- Expected: the change's own equivalence model (`REVERSE_STATUS_MAP`: Verified→done, `youtrack-projection.js:27-35`; sweep treats Verified as done-equivalent, `youtrack-status-sweep.js:24-31`) and FR-7 ("Verify SHALL preserve done while resolving the tracker card") require equivalent states to count as converged.
- Trigger: operator clicks Verify → tracker Verified, spec done → next sync issues `State Fixed`, reverting the governed action.
- Impact: tracker workflow states richer than the 3-value spec model are destroyed each sync; Verify is unobservable one sync later.

**correctness-3 — P2 — `src/adapters/youtrack-projection.js:353-366` — 'Done when:' mislabeled for the corpus's dominant field forms**
- Observed: extraction and strip regexes require `Done When:` + newline + `- ` bullet block. Single-line `Done when: text` and bulleted `- **done when:** text` — both parsed as the field by the kernel (`attributes.js:13-37,169`) and dominant in the corpus (73 `spec_entities` matches) — survive into `### Что делаем`.
- Expected: readiness conditions land under `### Условия готовности` (or are stripped) for every field form the kernel recognizes (AC-9.1).
- Trigger: any TASK body with `Done when: <single line>` or `- **done when:** <text>`.
- Impact: user-facing mislabeled card content on most synced TASK cards.

**correctness-4 — P2 — `scripts/spec-graph-sync.mjs:785-806` — sync lock TOCTOU on stale-lock takeover**
- Observed: on EEXIST → read pid → `kill(pid,0)` → `rm(force)` → retry `open('wx')`, with no identity check that the removed file is the one read; a contender arriving between a live holder's `open()` and `writeFile()` reads an empty file (NaN pid → treated dead) and deletes a live lock.
- Expected: atomic compare-and-delete takeover so two contenders cannot both hold the lock (stated purpose at `:779-784`: serialize same-host runs, prevent double pointer creation).
- Trigger: two syncs start against a stale lock (or one arrives in the open→writeFile gap) → both acquire.
- Impact: the serialization guarantee is void exactly in the crash-recovery window it targets; deterministic pointer dedup bounds permanent damage but concurrent writes interleave.

**correctness-5 — P2 — `scripts/spec-graph-sync.mjs:1154-1167` — `--serve` ignores `--dry-run`**
- Observed: `parseArgs` accepts both flags (`:838-839`) with no incompatibility check; `main()` branches to `startServe` before the dryRun-aware sync at `:1175`; `args.dryRun` is never consulted on the serve path; writeback hardcodes `dryRun:false` (`:217`).
- Expected: `--dry-run` suppresses all mutation or is rejected with `--serve`.
- Trigger: `node spec-graph-sync.mjs --serve --dry-run` → first tracker event performs a real `spec_patch`; periodic sweep applies real writes.
- Impact: a flag promising no writes performs irreversible tracker/spec mutations.

**correctness-6 — P2 — `src/adapters/youtrack-projection.js:499-520` — scoped `sync({specSlugs})` deletes out-of-scope owned cards**
- Observed: `readBoard({specSlugs})` scopes `plan.issues`, then `removeStaleCards` runs that scoped wanted-set against the full tracker issue list and the unscoped committed `cardIds` map (`spec-graph-sync.mjs:591-611`) — every owned card outside the scope is deleted.
- Expected: stale-card deletion restricted to the same scope (or skipped when `specSlugs` non-empty), matching the documented scope semantics (DESIGN.md).
- Trigger: `service.sync({specSlugs:['demo']})` after a prior full-corpus commit → mass deletion of other specs' cards. Reachability caveat: no shipped caller passes `specSlugs` today (tests only), but it is a designed, documented parameter of the exported service.
- Impact: mass deletion of valid tracker cards on first programmatic scoped sync.

**correctness-8 — P2 — `scripts/spec-listener-ensure.mjs:108-141` — cannot recover a live listener holding a stale token**
- Observed: probe fails HMAC under a rotated token (`:44-66`, rotation path `:78-90`) → spawn → EADDRINUSE → `spawn-failed` exit 3 on every invocation; the script never kills the stale process it spawned.
- Expected: terminate the stale listener or report a distinct actionable state.
- Trigger: `SPEC_WRITEBACK_TOKEN` rotated or `~/.omp/spec-writeback-token` regenerated while an old listener runs → permanent spawn-failed loop.
- Impact: writeback listener down until manual kill; sweep remains the only convergence path; failure surfaced but with no remediation.

**security-1 — P2 — `tools/spec-graph-app/widgets/spec-panel/index.html:86-113` (and `spec-board/index.html:740-769`) — widgets consume the SPEC:SYNC-STATE marker without the HMAC verification the sync mandates**
- Observed: `loadCommittedSnapshot` selects the lowest-id issue with `SpecId=SPEC:SYNC-STATE`, checks only the description prefix and JSON shape, then renders `marker.snapshot` and derives issue links from `marker.cardIds`; `marker.signature` is never read. The sync side verifies HMAC via `timingSafeEqual` and rejects unsigned markers (`spec-graph-sync.mjs:654-676`); the widget comment claims it applies "the same gate" — it applies only the SpecId half.
- Expected: per the change's own invariant ("marker trusted only if HMAC-verified") and DESIGN.md's "same gate the sync uses" claim, the widget should not present an unverifiable pointer as the authoritative committed snapshot.
- Trigger: a SPEC-project member (the threat model's named attacker, `spec-graph-sync.mjs:616-626`) plants a forged pointer winning by lowest id, or >50 forgeries evicting the real pointer past the fixed `$top=50` page (`spec-panel:90`).
- Impact: attacker-controlled titles/states and links to attacker-chosen issues rendered as the authoritative board — phishing/confusion vector. Bounded: `escapeHtml` prevents XSS, writeback stays fail-closed on verified `cardIds`, next publish deletes forgeries; no spec mutation possible.
