### Confirmed findings
- **Finding ID**: `correctness-1`
  - **Priority**: `P1`
  - **File**: `scripts/check-specs-repo-protection.mjs:44-81`
  - **Observed behavior**: Helper function `api()` calls `fail()` on any non-2xx HTTP status code (`!response.ok`), which immediately halts execution via synchronous `process.exit(1)`. In lines 74-81, queries for repository rulesets (`/repos/${repo}/rulesets`) and default branch protection (`/repos/${repo}/branches/${info.default_branch}/protection`) attempt to handle missing configuration or permission limits via `try/catch` and `.catch(() => "none")`. Because `api()` calls `process.exit(1)` rather than throwing an Error or rejecting the returned Promise, Node.js terminates immediately upon receiving HTTP 404 (the standard GitHub REST response when a branch has no protection enabled). The catch handlers are unreachable.
  - **Expected behavior**: Per the documented operational contract in `docs/specs-repo-operations.md:22-25` and the script specification (`scripts/check-specs-repo-protection.mjs:18-20`), branch protection and ruleset presence are report-only hardening metrics that must surface status (`"none"`, `"enabled"`, `"unreadable"`) in the posture JSON report without failing the script or aborting when hard gates (private repository status and collaborator boundaries) are satisfied. Non-2xx responses for report-only endpoints must not trigger a fatal `process.exit(1)`.
  - **Trigger scenario**: An operator runs `npm run check:specs-repo` against a private repository meeting all hard gates (private, collaborators within allowed set) where the default branch does not have branch protection configured. `GET /repos/${repo}/branches/main/protection` returns HTTP 404 (`Branch not protected`). `api()` invokes `fail()`, which calls `process.exit(1)`, aborting with an error message before emitting the posture JSON report.
  - **Impact**: The posture check script unconditionally fails with exit code 1 on standard GitHub private repositories that lack branch protection rules, breaking CI/CD checks and operator posture verification despite adhering to all defined security boundaries.
  - **Evidence**:
