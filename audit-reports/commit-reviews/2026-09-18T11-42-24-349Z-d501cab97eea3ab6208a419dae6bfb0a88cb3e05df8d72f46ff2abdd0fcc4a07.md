### Confirmed findings

**1. P2 correctness — Design-review gate docstring regex diverges from the gherkin parser; ≥4-space-indented opener bypasses Scenario: detection**
- File: `src/authoring/design-review.js:4` (added line; same defect duplicated at `src/enforcement/classifier.js:16` FEATURE_DOCSTRING_RE)
- Observed: `DOCSTRING_MARKER_RE = /^[ ]*("""|```)/u` treats a docstring marker indented by ANY number of spaces as a docstring opener; `hasScenarioHeader` then skips every following line — including real `Scenario:`/`Scenario Outline:` headers — until a matching marker. The gherkin parser it claims to mirror uses `DOCSTRING_RE = /^[ ]{0,3}("""|```)/u` (src/kernel/parsers/gherkin.js:13): a marker indented ≥4 spaces is NOT a docstring to the parser — it falls through as a stray line (gherkin.js:172 `current===null → continue`, :215-218 descriptionLines) and a following `Scenario:` line IS parsed as a real scenario.
- Expected: the gate's docstring model must match the parser exactly (0–3 space opener indent) so every line the parser can interpret as a scenario header is visible to the gate; the code comment claims exact parity ("Mirrors the gherkin parser").
- Trigger: `spec_patch` intent=patch with a content-carrying op (replace_document/append_to_section/create_document) writing `.feature` bytes `    """\nScenario: smuggled\n    """` — gate sees docstring body, parser sees a scenario; patch APPLIES with no designReview. Preflight misses identically.
- Impact: deterministic bypass of the release's headline governance control on BOTH the server gate and the host preflight mirror — DESIGN_REVIEW_REQUIRED never fires while the kernel indexes a real scenario.
- Evidence: src/authoring/design-review.js:4,6-19; src/enforcement/classifier.js:16; src/kernel/parsers/gherkin.js:13,105-112,172,215-218; src/authoring/proposals.js:791. Triage: lie (comment claims parity the code does not have).
