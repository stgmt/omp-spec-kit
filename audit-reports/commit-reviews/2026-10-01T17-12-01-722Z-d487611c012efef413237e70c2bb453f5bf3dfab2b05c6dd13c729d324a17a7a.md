### Confirmed findings

**security-1 — P2 — `src/adapters/marker-secret.js:43-47`**
- Observed: `resolveMarkerSecret` fails closed on a set-but-short `SPEC_SYNC_MARKER_KEY` env value (lines 31-42, with a comment naming exactly this silent-divergence hazard), but a persisted key file shorter than `MARKER_SECRET_MIN_LENGTH` (32) is silently discarded — resolution falls through to the secretsKey-derived digest, a freshly generated key, or the publicly-computable `digest('projection-marker:unkeyed')` (lines 48-58), with zero diagnostics.
- Expected: a present-but-invalid key file is the same invalid-explicit-secret condition as the env arm — refuse loudly or surface a distinguishing error instead of silently resolving to a value no other party shares.
- Trigger: operator aligns service and listener via the documented shared-file deployment (header lines 8-16) and the mounted `~/.omp/spec-sync-marker-key` is truncated: the service (no allowGenerate — index.js:44-47) resolves `digest('projection-marker:'+secretsKey)` while the listener (allowGenerate=true) generates a fresh random key → every writeback ownership check 409s silently forever. With `secretsKey=null` (bootService default) the service instead signs with the publicly-computable unkeyed digest, so any SPEC-project member can forge a signed `SPEC:SYNC-STATE` pointer whose cardIds map authorizes writeback `spec_patch` calls and stale-card deletions.
- Impact: silent permanent marker-signature divergence (all writeback events 409, sweep applies nothing), or — unkeyed path — complete bypass of the marker-ownership gate protecting tracker→spec writeback.
- Evidence: marker-secret.js:31-42 (env fail-closed arm + rationale comment), :43-47 (short file silently ignored), :48-58 (derived + unkeyed public fallbacks), :8-16 (shared-file deployment documented), src/service/index.js:44-47 (no allowGenerate), src/adapters/youtrack-store.js:421-430 (cardIds is the sole ownership proof).
