### Confirmed findings

**P2 — correctness-1: Mount-blind republish re-signs mount certification the reader never measured; cheapCheck then skips repair forever**
- File: src/adapters/youtrack-projection.js:524-532 (also src/adapters/youtrack-store.js:516-535, src/service/projection.js:150-178, scripts/spec-graph-sync.mjs:793-794)
- Observed: when `pointer.valid`, `sync()` copies committed `mountHeads`/`mountsClean`/`specProjects`/`skippedProjects` into the plan via `plan[field] ??= pointer[field]` for readers that emit none (local `McpBoardReader` — the parseArgs default when `SPEC_REGISTRY_URL` is unset). `publishCommitted` HMAC-signs those fields into the new marker. Service `cheapCheck` trusts `mountsClean===true` + recorded per-mount HEADs and never compares the marker fingerprint/snapshotHash against the mounts' real board.
- Expected: a marker mount certification may only attest mounts actually measured by that sync; a mount-blind republish must not let `cheapCheck` conclude mounts-unchanged when the committed snapshot was authored from a different corpus.
- Trigger: run `node scripts/spec-graph-sync.mjs` without `SPEC_REGISTRY_URL`, `OMP_SPEC_KIT_ROOT` pointing at a checkout whose HEAD equals the service mount HEAD but whose spec tree diverges (dirty/stale working tree). The republish writes diverged cards + a fresh fingerprint while preserving `mountsClean:true` and matching `mountHeads`; every later service `doSync` passes `cheapCheck` and returns SKIPPED.
- Impact: permanent silent divergence — the YouTrack board reflects the diverged local corpus instead of the mounts canonical specs; the service self-healing rebuild path is short-circuited until a mount HEAD moves, with no error surfaced.
- Evidence: youtrack-projection.js:521-532 (`??=` preservation); youtrack-store.js:516-535 (fields written then signed); projection.js:150-178 (cheapCheck trusts them) and :184-190 (doSync returns SKIPPED); spec-graph-sync.mjs:793-794 (`httpMode = args.registryUrl !== ''` — local mode still the default); youtrack-projection.js:340-344 (blind readers emit null mount fields, so `??=` re-injects the stale certification).

**P2 — correctness-2: HttpBoardReader silently resolves canonicalId/slug collisions that mergedBoard treats as fatal, then signs the corrupted routing map**
- File: scripts/spec-graph-sync.mjs:329-340 (also src/service/projection.js:95-110, src/adapters/youtrack-store.js:529/535, scripts/spec-graph-sync.mjs:363-386)
- Observed: `HttpBoardReader.readBoard` drops duplicate canonicalIds with `seen.has -> continue` and claims slug ownership first-wins with `served[slug] ??= project` over alphabetically-sorted projects — no error, no log. The derived `served` map becomes `board.specProjects`, is signed into the committed marker, and drives `HttpTaskStatusWriteback` spec_patch routing. The service-side `mergedBoard` throws on the identical conditions (duplicate-spec-node and spec-served-by-both errors).
- Expected: the registry-mode reader must fail the sync on a collision — the same contract the service enforces — because writeback routing is ambiguous and any silent winner is arbitrary.
- Trigger: committed marker `specProjects` is stale mid-migration — slug `s` mapped to `a/p` but also served by `b/p`. Both boards report `s`; the alphabetical-first project wins; the republished signed marker re-asserts that winner; a later writeback for `s:TASK-1` spec_patches the wrong (in-scope) mount, and each republish re-derives the same wrong winner.
- Impact: misrouted tracker writebacks (bot commits on a mount that no longer owns the spec, bounded to the token scopes by dispatch.js:106-112 scope checks) and silently dropped nodes; the corrupted routing is re-signed each sync and never self-corrects.
- Evidence: spec-graph-sync.mjs:329-340 (silent dedupe/first-wins), :354 (served -> specProjects), :363-386 (writeback routes from signed map); projection.js:95-110 (service throws on same conditions); youtrack-store.js:529/535 (specProjects signed into marker); dispatch.js:106-112 (scope check bounds but does not eliminate the defect).
