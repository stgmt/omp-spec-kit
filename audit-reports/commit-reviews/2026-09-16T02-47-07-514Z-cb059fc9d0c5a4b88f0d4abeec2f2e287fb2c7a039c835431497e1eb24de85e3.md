### Confirmed findings

**P2 — `correctness-1` — Local tag creation without existence check crashes publish retry on transient push failure**
- **File**: `src/service/publish.js:115-124`
- **Verifier Argument**: `publishSpecNow` invokes `git.tag` without checking if the local tag already exists in the clone worktree and without catching collision errors or passing `--force`. When `git.push` fails immediately afterward (e.g. transient network or remote rejection), the local tag remains created while `remoteSha` and `ledgerRow` remain null. Subsequent publish retries re-execute `git.tag` and crash with `fatal: tag already exists` (exit 128), permanently wedging publication retries for that version.
- **Counterexample**: Publish an ACTIVE spec; local `git.tag` succeeds, but `git.push` encounters a transient network glitch or remote timeout. On the next publish retry, `remoteSha` is still null on the remote, so `git.tag` is called again and throws `fatal: tag already exists`.

**P2 — `correctness-2` — Inverted winner check re-throws push error instead of adopting remote tag on concurrent publish**
- **File**: `src/service/publish.js:122-132`
- **Verifier Argument**: In `publishSpecNow`, when `git.push` fails in the catch block at line 122, it re-queries remote tags via `git.lsRemote` and checks `if (!winner || winner === headSha) throw error;`. This condition is inverted: when `winner === headSha`, a concurrent worker or process successfully pushed the tag for the exact same commit. Instead of adopting or recording this tag, the handler re-throws the git push error (e.g. `fatal: [rejected] (already exists)`), failing the publish operation and omitting the local ledger entry.
- **Counterexample**: Two concurrent processes publish an ACTIVE spec at the same commit `headSha`. Worker 1 pushes the tag. Worker 2's push is rejected with `[rejected] (already exists)`. Worker 2 queries `lsRemote`, sees `winner === headSha`, and re-throws the push rejection error instead of adopting or recording the publication into its ledger.
