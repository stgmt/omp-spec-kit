### Confirmed findings

**P1 — correctness-1** — `src/adapters/youtrack-status-sweep.js:26-28`. Writeback and sweep skip every bulleted-Status task (~40% of the live corpus: 30/76 TASKs report `taskStatus='unknown'` because `FIELD_RE` at `src/kernel/parsers/attributes.js:13` never matches `- **Status:**`), while `buildProjectionPlan` (`youtrack-projection.js:260-262`) uses a `parseTaskStatus(node.body)` fallback that *does* match bullets. A tracker-side Approve on such a task produces `action:'skip'` (spec_patch never called), then the next sync's `upsertCards` reverts the tracker State back to Open. Tracker and spec permanently disagree while both report success; DESIGN.md's claim that spec_patch "honors every Status field form the kernel parses (…bulleted)" is false.

**P2 — correctness-2** — `src/kernel/query/service.js:763-765`. Synthetic ROADMAP node emits `canonicalId '<slug>:ROADMAP:ROADMAP'`; `splitCanonicalId` returns null (verified), so the kernel's own `canonicalId()` validator rejects it with INVALID_PARAMETER on getNode/findNodes, and the tracker card SpecId violates the declared `<specSlug>:<localId>` grammar (FR-2/SCHEMA).

**P2 — correctness-3** — `tools/spec-graph-app/widgets/spec-board/index.html:1269-1314`. `drawV1Wires` positions SVG paths from `getBoundingClientRect()` of cards inside per-lane scroll containers, but no scroll listener/ResizeObserver/rAF exists anywhere in the file; wires redraw only on initial render and zoom, and `scrollIntoView` (line 1228) scrolls lanes without redrawing. With 76 TASKs, lane overflow is guaranteed — wires detach and show false/dangling lineage on the primary board view.

**P2 — correctness-4** — `.specs/roadmap-roadmaps/TASKS.md:8,40,53`. Three of four cross-spec `Implements` links point at wrong requirements: TASK-1→FR-30 (discovery metadata; correct target FR-33 type dictionary), TASK-3→FR-16 (waiver honesty), TASK-4→FR-37 (validation inspection; correct target FR-39 board view). All three materialize as real IMPLEMENTS edges (verified live) and propagate to tracker cards.

**P2 — correctness-5** — `.specs/youtrack-visualization/FILE_CHANGES.md:3-5`. "Current defect" claims `scripts/spec-graph-sync.mjs` is a legacy composition root being fixed and TASK-10 "Remove legacy graph reconstruction" is done — but the file is NEW in this diff (absent at HEAD, verified via `git cat-file`), already written against ports; nothing was removed. RESEARCH.md RF-2/RF-3 repeat the fictional baseline. Spec-integrity defect.

**P2 — correctness-6** — `src/adapters/youtrack-projection.js:400-401`. `desiredSummary` slices at 500 chars while kernel titles allow 512 and YouTrack summaries are limited to 255; `upsertCards` has no per-card try/catch, so one 256–512-char heading aborts the entire sync before link reconciliation and marker publish, on every run.

**P2 — security-1** — `tools/spec-graph-app/widgets/spec-board/index.html:734-743` (identical at `spec-panel/index.html:80-89`). Widgets select the committed snapshot by `summary: {SPEC:SYNC-STATE}` + lowest id with no HMAC check, while the sync selects/dedups pointers by the `SpecId` custom field (`spec-graph-sync.mjs:637-640, 690-695`). A SPEC-project member who creates a summary-matching issue without the SpecId field produces a forged pointer the widgets render but the sync never sees or deletes — durable spoof of the authoritative graph for all viewers.

**P2 — security-2** — `scripts/spec-listener-ensure.mjs:44-49`. `probe()` accepts any HTTP 200 on `/health`; the listener's `/health` is unauthenticated and generic (`spec-graph-sync.mjs:891-894`). Any foreign process on port 8787 suppresses the real listener ("alive" short-circuit) while `spec-writeback.js` keeps POSTing `X-Spec-Writeback-Token` to that port — token disclosure plus silent writeback outage.

**P2 — security-3** — `tools/spec-graph-app/spec-writeback.js:19-20,52-55`. The sole `/writeback` auth factor is sent as a bearer header over hardcoded cleartext `http://host.docker.internal:8787` across the Docker host bridge on every State change; a captured token enables unlimited authenticated event flooding (durable outbox + serialized MCP-child jobs). Status injection stays blocked by tracker re-verification, bounding impact to availability/audit noise — but no spec doc acknowledges or justifies the cleartext transport.
