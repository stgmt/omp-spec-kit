### Confirmed findings

**correctness-1 — P2 — `src/authoring/elicitation-guard.js:18-23`** — *Ticket eviction runs before the `has()` check, so a no-op re-add at capacity destroys an unrelated ticket.*

- **Observed**: `_remember` deletes the oldest recorded ticket whenever `_recorded.size >= MAX_ELICITATION_TICKETS` (10 000) and then calls `add(key)`. When `key` is already present, `add()` is a no-op: the set shrinks to 9 999 and an unrelated spec/document ticket is destroyed. `checkAndRecord` (lines 44-53) invokes `_remember` for every candidate doc in a refusal batch — including already-recorded docs — whenever at least one candidate is unrecorded.
- **Expected**: re-adding an already-recorded key must not evict anything; eviction should only run when inserting a genuinely new key would exceed the bound. Per `.specs/agent-ux-elicitation-guard/FR.md` FR-5, a recorded ticket protects its target from a second refusal for the cached service lifetime.
- **Trigger**: accumulate 10 000 recorded tickets in one cached `SpecPatchService` lifetime; then an apply whose proposal creates new missing doc B alongside already-refused doc A — `allRecorded` is false, `_remember(A)` evicts the oldest unrelated ticket for still-missing spec X/doc Y while `add(A)` is a no-op; a later first-creation apply for X/Y is refused a second time.
- **Impact**: one redundant `REFUSED`/`ELICITATION_REQUIRED` nudge for an unrelated still-missing document (fail-safe direction, zero bytes written, retry still commits); each no-op re-add at capacity also silently shrinks the ticket set below the bound. Minor severity, but a pure logic error violating FR-5's letter for the evicted doc.
- **Evidence**: `src/authoring/elicitation-guard.js:18-23` (delete precedes add, no `has()` guard); `:44-53` (`_remember` per candidate doc on every non-allRecorded refusal); `src/authoring/service.js:244` (unconditional `checkAndRecord` inside `withWriteLock`; guard is sole ticket owner); `tests/authoring-elicitation-edges.test.mjs` capacity test inserts only distinct keys — re-add-at-capacity uncovered; `FR.md` FR-5; `NFR.md` NFR-DETERMINISM-1.
