### Confirmed findings

**P1 — correctness-1 — `src/adapters/youtrack-status-sweep.js:38-51`** — Status sweep and writeback regress unrepresentable spec task statuses to `todo`.
- *Observed*: `STATUS_MAP` covers only planned/todo/done (`youtrack-projection.js:21-25`); `in-progress`/`ready`/`blocked`/`deferred`/`unknown` project to tracker `Open` via `parseTaskStatus` fallback (`:183-187,261-263`). The sweep maps `Open`→`todo`, sees `trackerStatus≠specStatus` with `specStatus==snapshotStatus`, and plans a `spec_patch` write of `todo`. `handleWritebackRequest` (`spec-graph-sync.mjs:747-750`) patches unconditionally on any mappable state — including the sync's own `State Open` command echoing back through the onChange rule. Reproduced live: `planStatusSweep({in-progress, Open, baseline in-progress}) → [{status:'todo'}]`.
- *Expected*: statuses the tracker cannot represent must never be written back; lossy projections should be skipped (spec wins).
- *Trigger*: set a task to `in-progress` (legal per `TASK_STATUSES`, `types.js:278-288`), run one sync, then the `--serve` sweep (default 300 s) or any State change rewrites `TASKS.md` to `todo`.
- *Impact*: silent data regression in the authoritative `.specs` corpus — 5 of 8 governed statuses cannot survive one sync+sweep cycle.

**P1 — correctness-2 — `tests/helpers/tool-e2e.mjs:133-134`** — Stale 15/7 descriptor-count assertions break the release-archive smoke gate.

The phase runs under default `phase='all'`, used by `scripts/smoke-release-archive.mjs:97-102`, invoked by `release.yml:51`, `distribution-evidence.yml:107`, `release-preflight.mjs:58` against the packaged dist server (staged with the same 16/8 kernel). The staged board assertions at `:187-195` sit in the same unreachable-under-`npm test` phase.
- *Expected*: count assertions updated to 16/8 alongside the kernel change.
- *Trigger*: any release/distribution-evidence workflow run or archive smoke against a build from this tree.
- *Impact*: every release pipeline fails at the archive smoke step; the board view simultaneously has zero executed e2e coverage in the standard suite.

**P2 — correctness-3 — `.specs/youtrack-visualization/youtrack-visualization.feature:20-30`** — New spec contradicts code and itself on link types and board kinds.

- *Expected*: normative text states nine link types and six board kinds, matching FR-3 and the implementation.
- *Impact*: spec-of-record is wrong and self-contradictory for the feature this change ships.

- *Expected*: feature says 8 edge types; SCHEMA/FR-39 board-kind lists include ROADMAP.
- *Impact*: normative spec text disagrees with shipped behavior and with the spec's own FR-33 in the same commit.

**P2 — correctness-5 — `src/adapters/youtrack-projection.js:409-415`** — `fieldValue` cannot read text-typed custom fields the writer itself supports.
- *Observed*: `fieldValue` returns `value.name ?? value.presentation ?? ''`; a `TextFieldValue {text}` reads as `''`. The writer branches on `valueType 'text'` and writes `TextFieldValue` for SpecId/ContentHash/Evidence (`spec-graph-sync.mjs:331-341,352-364`).
- *Expected*: read/write symmetry — `fieldValue` reads `value.text`, or the writer refuses text-typed identity fields.
- *Trigger*: SPEC project provisions SpecId as a text field → `bySpecId` empty → every sync recreates all cards, ownership gate defeated, permanent `CARD_DRIFT`, writeback re-verification 409s.
- *Impact*: duplicate cards on every sync and total projection failure under a field type the code itself writes.

**P2 — correctness-6 — `scripts/spec-graph-sync.mjs:208-228`** — `YouTrackClient` has no request timeout; one hung tracker call stalls the serialized serve chain.
- *Observed*: bare `fetch` with no `AbortSignal`/deadline, unlike the MCP client (`MCP_CALL_TIMEOUT_MS:53`). In `--serve`, all writeback jobs and sweeps serialize through one `chainRef` (`:729-752,784-790`). Bounded to ~5 min by undici defaults; a trickling response can stall indefinitely.
- *Expected*: explicit timeout/abort on tracker calls.
- *Impact*: multi-minute to indefinite silent stall of all writeback and sweep processing.

**P2 — security-1 — `scripts/spec-graph-sync.mjs:744-750`** — Writeback and sweep trust attacker-editable SpecId as task-ownership proof.
- *Observed*: re-verification checks only project `SPEC`, tracker-held `SpecId===event.specId`, `SpecKind==='TASK'`, mappable State — all editable issue fields. The committed snapshot's `cardIds` ownership map (which `removeStaleCards:498-503` treats as the only ownership proof) is never consulted; `listTaskCards:503-517` has the same gap.
- *Expected*: writeback/sweep act only on SpecIds recorded in the committed snapshot's `cardIds`.
- *Trigger*: a SPEC-project editor sets `SpecId='victim:TASK-3'`, `SpecKind=TASK` on their own issue and moves State → writeback or next sweep flips the victim task's status.
- *Impact*: cross-task status forgery — any SPEC editor can rewrite any real task's status in the corpus.

**P2 — security-2 — `scripts/spec-graph-sync.mjs:181-190`** — Writeback entity resolution uses substring heading match.
- *Observed*: `setSpecTaskStatus` passes the entity verbatim to `spec_patch`; downstream `replace_task_status` resolves via `line.includes(operation.entity)`, first match wins (`src/authoring/proposals.js:154-161`, pre-existing matcher, new remote caller).
- *Expected*: exact local-id match; ambiguous entity fails closed.
- *Trigger*: `## TASK-10` precedes `## TASK-1` in TASKS.md → a writeback for `TASK-1` mutates `TASK-10`; with security-1 the attacker picks the substring.
- *Impact*: silent wrong-task status mutation, remotely triggerable.

**P2 — security-3 — `scripts/spec-graph-sync.mjs:701-703`** — Writeback listener ships unauthenticated on the documented `host.docker.internal` path.
- *Observed*: token check skipped when `SPEC_WRITEBACK_TOKEN` unset; `parseArgs` requires a token only for non-loopback binds (`:643-646`); shipped rule posts to `http://host.docker.internal:8787/writeback` with `LISTENER_TOKEN=''` (`spec-writeback.js:16-18`); `spec-listener-ensure.mjs:48-56` spawns `--serve` tokenless. On Docker Desktop, `host.docker.internal` reaches host loopback from any container.
- *Expected*: token mandatory on the shipped deployment path.
- *Impact*: unauthenticated endpoint — outbox spam, confused-deputy authenticated tracker GETs, MCP child spawns, and (with security-1) unauthenticated spec mutation.

**P2 — security-4 — `scripts/spec-graph-sync.mjs:756-759`** — Writeback responses leak the absolute outbox path and tracker internals.
- *Observed*: every response embeds `outbox` (default under `os.tmpdir()` → discloses the Windows username); error bodies echo tracker-held SpecId/SpecKind and upstream error text with the internal YouTrack URL (`:745-746,772`).
- *Expected*: bounded status payload without filesystem paths or upstream error text.
- *Impact*: information disclosure to unauthenticated callers (per security-3), aiding further attacks.
