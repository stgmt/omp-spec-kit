### Confirmed findings

**P1 — security-1: Stored XSS in spec-board via unescaped `node.kind` in innerHTML**
`tools/spec-graph-app/widgets/spec-board/index.html:1564,1588` — `kind-${node.kind}` interpolated unescaped into `innerHTML` class attributes; `node.kind = KIND_LABELS[source.kind] || source.kind` (line 733) passes any unrecognized kind verbatim from the marker JSON, which lives in a plain tracker-issue description editable by anyone with Update Issue on SPEC. Marker validation (709-717) checks only schemaVersion/complete/page/arrays. `escapeHtml` exists and is applied to sibling fields — the omission is proven. Payload executes for every dashboard viewer on the V3 tab; `host.fetchYouTrack` runs with the viewer's session → privilege escalation from issue-edit to viewer-session API access.

**P2 — correctness-1: Writeback listener unreachable in the documented topology**
`scripts/spec-graph-sync.mjs:648` binds `127.0.0.1` while `tools/spec-graph-app/spec-writeback.js:15` posts to `http://host.docker.internal:8787` (host gateway interface in Docker staging; unresolvable on non-Docker installs). Every State-change event is silently lost (`console.warn` swallow), and the next sync's `upsertCards` (line 377) reverts the human's tracker change. Bounded by Phase-B deferral (ROADMAP, issue #31) — dead shipped path, fails on first activation.

**P2 — correctness-2: `buildProjectionPlan` maps links by endpoint kinds, ignoring `edge.type`, and fabricates `verifies` links**
`src/adapters/youtrack-projection.js:230-263` — any TASK→FR edge (incl. REFS, the dominant corpus pattern) becomes `implements`; AC→FR→`satisfied-by`; FR→AC→`satisfies`; FR→TASK→`implemented-by`; TASK→NFR→`constrains` (inverted semantics for legal IMPLEMENTS/REFS edges). The `testedBy×satisfiesOut` cross-product fabricates links absent from the kernel graph; `skippedLinks` is never surfaced. Staged DESIGN.md declares the mapping table the sole source and forbids guessing — the code contradicts its own staged spec; `sync.test.js` pins the violation.

**P2 — correctness-3: `linkEquivalenceKey` sorts endpoints — reversed links are undetectable drift**
`src/adapters/youtrack-projection.js:413-419` — `type|min|max` makes `depends-on A→B` identical to `B→A`; `readProjection` records links from the queried issue's side under the outward type name, so a physically reversed link reads as the desired direction. Parity reports PARITY, `reconcileLinks` skips both add and delete — permanent direction drift, violating AC-3.1 "truthful directions" and NFR-IDEMPOTENCE-1.

**P2 — correctness-4: Writeback outbox is write-only — failed writebacks are permanently lost**
`scripts/spec-graph-sync.mjs:601-604` — `appendFile` is the only outbox operation repo-wide; on `spec_patch` failure the endpoint answers 502, retains the draft, and nothing ever reprocesses it. The spec keeps the stale status and the next sync reverts the human's tracker change — the opposite of the FR-6 bidirectional-status contract.

**P2 — correctness-5: spec-board renders every non-{planned,todo,done} taskStatus as "Open"**
`tools/spec-graph-app/widgets/spec-board/index.html:724-726` — `TASK_STATES[source.taskStatus] || 'Open'` labels `unknown`/`ready`/`in-progress`/`blocked`/`deferred` as Open. Kernel provenance: `TASK_STATUS_NORMALIZATION` (types.js:279-285) lacks `done`/`Done`, so `Status: done` → `unknown` → rendered Open while the tracker card is Fixed. The board systematically misrepresents task state on the real corpus.

**P2 — correctness-6: spec-board defaults the spec filter to `youtrack-visualization`, not the full corpus**
`tools/spec-graph-app/widgets/spec-board/index.html:788-791` — `selectedSpec` hardcodes the slug when present; `defaultTarget` hardcodes `TASK-8`. FR-12 (staged): "All views SHALL default to the full corpus." Users see a partial graph believing it complete.
