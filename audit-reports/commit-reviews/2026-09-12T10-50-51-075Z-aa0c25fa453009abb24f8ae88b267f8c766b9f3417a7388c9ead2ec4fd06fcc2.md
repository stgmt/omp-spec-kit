YouTrack requires an `s`/`t` direction marker on the link id for directed types; `--provision` creates all nine types `directed:true`, and the code's own comment states inward-link intent, which needs the `t` marker that is never appended. Trigger: provision + sync over any corpus with mappable edges → attach fails mid-run after card upserts (or links created reversed → perpetual LINK_DRIFT; deletes 404-swallowed so stale links accumulate). The link layer is dead in production; no test exercises the real HTTP path (fake port only).
2. **P1 — correctness — `scripts/spec-graph-sync.mjs:182-199`** (new `McpTaskStatusWriteback` caller): writeback routes through `spec_patch setEntityStatus` → `replace_task_status`, whose status-line locator `/^\s*-\s+\*\*Status:\*\*/` (proposals.js:173) matches only the bulleted `- **Status:**` form. Kernel `FIELD_RE` (attributes.js:13) parses plain `Status:` and non-bulleted `**Status:**` too — the dominant corpus formats (all of youtrack-visualization and roadmap-roadmaps TASKS.md, spec-mcp-access-gate, spec-mcp-operations TASK-1..14). Trigger: tracker State change on such a card → VALIDATION_FAILED "task status field not found" on every writeback/sweep. The only bidirectional field silently fails for the majority of corpus tasks.
3. **P2 — correctness — `scripts/spec-graph-sync.mjs:314-331`**: undirected link types (`direction === 'BOTH'`) are recorded from both endpoints with a directional dedup key → the same physical link counted twice → perpetual LINK_DRIFT and delete/recreate churn on trackers with pre-existing undirected types.
4. **P2 — correctness — `src/adapters/youtrack-projection.js:404-406`**: `desiredDescription` formatter map lacks ROADMAP → generic fallback omits `relationsSection`; the synthetic ROADMAP card (sole owner of `contains` links) renders no grouped-relations section, violating FR-9/SCEN-readable-card for exactly the kind this diff adds.
5. **P2 — correctness — `scripts/spec-graph-sync.mjs:571-600`**: pointer find-or-create has no inter-process lock; two overlapping syncs both create SPEC:SYNC-STATE issues; `find()` + widget `$top=1` then read arbitrary duplicates → permanent split-brain committed state (DESIGN.md assigns locking to infrastructure; none exists).
6. **P2 — correctness — `scripts/spec-graph-sync.mjs:586-594`**: `publishCommitted` hardcodes `SimpleIssueCustomField` for SpecId while the card path is valueType-aware; on a project with text-typed SpecId the pointer create 400s after all cards/links are written → sync never commits, writeback ownership never exists.
7. **P2 — correctness — `tools/spec-graph-app/widgets/spec-board/index.html:1264-1270`**: `drawV1Wires` compares `link.type` (raw kernel types: REFS/IMPLEMENTS/…) to lowercase tracker link names → no match ever → every V1 wire renders default gray; spec-panel's EDGE_LABELS keys on kernel types correctly.
8. **P2 — correctness — `.specs/youtrack-visualization/youtrack-visualization.feature:72-76`**: SCEN-honest-type enumerates five Type values omitting Roadmap; FR-10, the SCHEMA doc, and `TYPE_PER_KIND` all define six — the spec-of-record is internally contradictory.
9. **P2 — security — `scripts/spec-graph-sync.mjs:561-569`**: `readCommitted()` trusts the first issue with SpecId `SPEC:SYNC-STATE` — no uniqueness/author/integrity check — and its description's `cardIds` + snapshot baseline are the sole ownership proof for listener and sweep. A SPEC-project member can forge the marker (copying real hashes so `canSkip` keeps it alive), map `cardIds` to an attacker card, and pin the baseline to defeat spec-moved-wins → arbitrary TASK-status writes into `.specs` under the daemon's credentials — the confused-deputy the cardIds gate was built to prevent.
10. **P2 — security — `scripts/spec-graph-sync.mjs:798`**: default outbox `path.join(tmpdir(), 'spec-graph-writeback.jsonl')` with symlink-following stat/rename/appendFile; on POSIX a local user can pre-plant a symlink (arbitrary file append as the listener user) or a directory (every writeback 500s → silent durable-outbox loss). The sibling helper already uses `~/.omp` mode 0o600.
11. **P2 — security — `scripts/spec-graph-sync.mjs:80`**: MCP stdio child spawned with `{...process.env}` inherits `YOUTRACK_TOKEN`/`YOUTRACK_PASSWORD` (admin-scoped — same client calls `/api/admin/projects`) and `SPEC_WRITEBACK_TOKEN`; the child needs none of them (zero `process.env` reads in `src/mcp/`), and the preferred server is the user-writable installed-plugin dist — silent credential exposure on every call.
