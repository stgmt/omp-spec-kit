# Функциональные требования

## FR-1 — Один файл проекта
Кит хранит один авторитетный `GLOSSARY.md` на проект и связывает его с идентичностью проекта и репозитория. Все спецификации и ветки этого проекта разрешают один и тот же файл; запись в файл конкретной спеки не создаёт общую копию. При общей репозитории двух проектов их источники изолированы. Каждое чтение возвращает версию содержимого, сохраняемого в истории. Уполномоченный читатель может через MCP запросить историческую версию; для записи спеки принимается только актуальная версия.

## FR-2 — Обнаружение и чтение
Refs: spec-mcp-operations:FR-30
Инструкции MCP при подключении, описание инструментов и отказ при содержательной правке сообщают, что общий глоссарий обязателен, как его найти и прочитать. Проектно-адресуемые варианты существующих MCP-инструментов позволяют узнать состояние, прочитать весь файл с версией и искать каноническое слово или явно указанную форму. Поиск возвращает определение, статус формы и версию файла. При ограничении ответа возвращается признак усечения; частичный ответ не выдаётся за полный.

## FR-3 — Создание и редактирование
Refs: spec-mcp-operations:FR-24, spec-mcp-operations:FR-26
Уполномоченный автор создаёт файл для проекта через MCP до первой содержательной правки спеки. Дальнейшее добавление, изменение и удаление терминов проходит через MCP с предварительным просмотром, ожидаемой версией и атомарным применением. Отсутствующий файл не заменяется данными из отдельной спеки или образцом. При неопределённом значении агент не выдумывает его, а фиксирует вопрос и не объявляет термин согласованным.

## FR-4 — Проверка актуальной версии
До содержательного изменения спецификации автор получает текущий файл и передаёт его версию при предварительном просмотре и применении. Сервер проверяет версию повторно непосредственно перед сохранением, согласуя её с конкурирующей записью глоссария через общий механизм взаимоисключения или эквивалентную атомарную проверку. Отсутствие, недоступность или несовпадение версии блокирует изменение без частичной записи и сообщает, как восстановиться. Проверка подтверждает предъявление актуальной версии, а не понимание или прочтение агентом.

## FR-5 — Термины и ошибки
Refs: spec-mcp-operations:FR-31
При проверке кандидатного текста сервер определяет явно перечисленные запрещённые формы, учитывая границы слов и нормализацию, определённые в схеме. Для каждой находит документ и место, форму и каноническую замену. Ненайденный новый термин не считается доказанно корректным: подсказка требует содержательно сверять новые термины с владельцем и обновлять глоссарий перед их употреблением. Ошибки различают отсутствие, недоступность, неподходящую версию, нарушение формата, запрещённую форму и недостаток прав; каждая содержит безопасный следующий шаг.

## FR-6 — Изоляция и разрешения
Чтение и запись учитывают выбранный проект, авторизацию и действующие роли реестра. Отказ за пределами доступа не раскрывает содержимое или существование файла чужого проекта. Недостаток прав не интерпретируется как отсутствие файла. Предварительный просмотр не создаёт и не меняет ветку, файл или другие постоянные данные. Единственный путь изменения авторитетной ветки — проверенный сервисный путь; обычный пользователь не может обойти MCP прямой записью в эту ветку.

## FR-7 — Состязательные изменения и сбои
Запись с устаревшей версией отклоняется целиком; актуальный источник перечитывается перед повторной правкой. Ошибки хранилища, сбой сети и конфликт параллельных авторов не дают ложного успеха. Повтор с тем же идентификатором запроса не создаёт вторую запись; результат различает подтверждённое применение и неизвестный исход.

## FR-8 — Запуск без циклической зависимости и доставка
Refs: spec-readiness-gate:FR-6
Подключение проекта, чтение статуса, помощь и создание первого файла доступны без ранее созданного глоссария. До создания содержательные правки спецификаций блокируются с указанием порядка настройки; чтение существующих спецификаций остаётся доступным. После реализации одинаковые правила действуют в локальном и сетевом MCP для зарегистрированного проекта, без отдельного локального режима без реестра, а установленный сервер и подсказки проверяются реальными MCP-вызовами, а не только внутренней функцией.
